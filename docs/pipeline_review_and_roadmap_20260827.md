# Robot Grasp 管线评审与改进路线

日期：2026-08-27

## 1. 结论

当前 `robot_grasp` 已经是一个结构清晰的离线工程原型，完成了数据契约、理想深度建模、对象坐标系、
FoundationPose 接入、抓取候选管理、坐标组合和离线验收。但是，它还不是可以直接接到机器人上自主抓取的
完整管线。

当前阶段应定义为：**离线 PoC 完成，准备进入真实 RGB-D 与机器人实机闭环**。

已经得到证据支持的能力：

- RGB-D 序列格式、长度单位和 `T_dst_src` 坐标约定能够被严格校验。
- HouseCat6D 导入器正确闭环了 `T_camera_object`、`T_world_camera` 和 `T_world_object` 的方向关系。
- 理想 `depth_gt` 条件下，Open3D TSDF 的单位、外参方向和融合流程正确。
- FoundationPose 能够在不使用 GT pose 初始化的条件下独立执行 `register()`。
- `T_base_camera @ T_camera_object @ T_object_grasp` 的组合方向已由测试和 dry-run 验证。

尚未得到证据支持的能力：

- 真实 RGB-D 传感器数据能生成尺寸和表面均可靠的对象 Mesh。
- 在线实例分割能够稳定提供 FoundationPose 所需 mask。
- 抓取候选与真实夹爪几何、碰撞、IK 和可达性相容。
- 手眼标定误差加入后，`T_base_grasp` 仍满足任务精度。
- 机器人能够安全完成接近、闭合、抬升和失败恢复。
- 整条管线能够在多对象、多场景下达到稳定的实际抓取成功率。

## 3. 第一批结果分析

### 3.1 HouseCat6D 导入

第一轮选择 `val_scene1` 的 `cup-plastic_green_flowers`，从 695 帧中每隔 5 帧导入一帧，共 139 帧。

| 深度来源 | mask 内平均有效深度比例 | mask 内最小有效深度比例 |
|---|---:|---:|
| raw depth | 87.970% | 64.822% |
| `depth_gt` | 100.000% | 100.000% |

695 帧坐标闭环最大误差约为 `4.88e-16 m / 4.83e-6 deg`。这说明导入代码中的单位和变换方向正确，
但不说明实际相机标定或原始深度质量正确。

### 3.2 理想深度重建

高分辨率配置使用 1 mm 体素、4 mm TSDF 截断距离和 139 帧 `depth_gt`。

| 指标 | 重建 Mesh | 官方 Mesh | 绝对误差 |
|---|---:|---:|---:|
| X | 111.346 mm | 111.668 mm | 0.322 mm |
| Y | 84.913 mm | 85.478 mm | 0.565 mm |
| Z | 80.978 mm | 80.356 mm | 0.622 mm |

基于 150,000 个均匀表面采样点的近似诊断结果：

- 重建表面到官方 Mesh：平均约 `0.358 mm`，P95 约 `0.698 mm`。
- 官方 Mesh 到重建表面：平均约 `1.629 mm`，P95 约 `5.603 mm`。
- 重建表面积约 `0.0285 m^2`，官方 Mesh 约 `0.0431 m^2`，约为后者的 66%。

结论：已观察到的表面融合准确，但重建仍缺少内壁、底部或遮挡区域，不是完整 CAD 级模型。当前结果足以
验证管线方向，不足以单独证明碰撞 Mesh 完整可靠。

### 3.3 原始深度重建

| 处理方式 | 重建 AABB 尺寸 |
|---|---|
| 原始 mask | 188.679 x 108.876 x 112.552 mm |
| mask 腐蚀 3 px | 188.095 x 100.000 x 100.000 mm |
| 1%-99% 深度分位 | 187.261 x 111.449 x 108.486 mm |

与同帧 `depth_gt` 比较得到：

- mask 内绝对深度误差中位数约 `9 mm`，平均约 `13.1 mm`，P95 约 `37 mm`。
- `71.7%` 像素的误差超过 `5 mm`，`42.8%` 超过 `10 mm`。
- mask 腐蚀 3 px 后，超过 `5 mm` 的比例仍约 `71.1%`。
- raw depth 相对 `depth_gt` 的中位有符号偏差约为 `+7 mm`，约 79.7% 的有效像素偏远。
- 线性拟合约为 `raw_mm = 1.00417 * gt_mm + 5.585`，校正后绝对残差 P95 仍约 `36.7 mm`。

结论：主要问题不是 mask 边缘泄漏，而是原始深度本身存在明显系统偏差、视角相关偏差和长尾噪声。继续单独
调整腐蚀像素或全帧分位阈值不能解决问题。

### 3.4 FoundationPose

当前评测使用五个相隔 150 个原始帧的视角，每帧独立执行 `register()`：

| 指标 | 均值 | 中位数 | 最大值 |
|---|---:|---:|---:|
| 平移误差 | 6.129 mm | 5.232 mm | 8.978 mm |
| 旋转误差 | 0.786 deg | 0.839 deg | 0.884 deg |

转换到共同 `T_base_object` 后，最大两两差为 `8.878 mm / 1.569 deg`。当前验收中 Mesh 尺寸和旋转通过，
平移超过 5 mm 门槛，因此整体验收失败。

该结果需要按以下边界解释：

- GT pose 没有传入 FoundationPose，只在 `estimate()` 返回后用于评分。
- 输入使用了 GT visible-instance mask，没有覆盖在线分割误差。
- 推理 Mesh 来自同一场景和同一轨迹的 `depth_gt + GT pose` 重建。
- 只有 5 帧，不能可靠估计长尾失败率。
- 当前“重复性”样本来自不同视角，实际测量的是跨视角一致性，不是固定输入重复运行的随机重复性。
- `T_base_object` 使用数据集 GT 相机位姿组合，尚未加入真实手眼标定误差。

## 4. 主要代码与能力缺口

### 4.1 深度处理不足

当前重建只包含深度范围、mask、逐帧深度分位和小连通分量清理。缺少：

- 相机深度尺度与偏置标定。
- RGB-depth 对齐质量检查。
- 深度跳变和飞点检测。
- 局部中值、双边或引导滤波。
- 多视角重投影一致性检查。
- 基于 TSDF/ICP 残差的坏帧拒绝。
- 相机位姿局部优化或 RGB-D odometry 校正。

### 4.2 抓取数据没有转成可执行计划

`grasps.json` 已保存 `pregrasp_offset`、`approach_distance` 和 `gripper_width`，但 `compose-grasp` 只组合
`T_base_grasp`。当前还需要定义统一的 `GraspPlan`，至少输出：

```text
T_base_pregrasp
T_base_grasp
T_base_retreat
gripper_open_width
gripper_close_width_or_force
approach_speed
retreat_speed
selected_grasp_id
planning_and_collision_status
```

候选选择顺序应从“先按 priority 选择”改为“先组合到 base、检查 IK/碰撞/路径，再对可执行候选排序”。

### 4.3 查看器没有真实夹爪模型

当前查看器只显示对象和 TCP 坐标轴。需要加载目标夹爪 URDF 或简化碰撞几何，同时显示：

- 开口宽度与闭合方向。
- 指尖接触区域。
- pregrasp 到 grasp 的扫掠体积。
- 与对象 Mesh、桌面和环境的碰撞状态。
- IK 可达状态和候选失败原因。

### 4.4 验收指标过弱

Mesh 验收目前只比较对象坐标系下 AABB。AABB 正确不能排除孔洞、局部漂移和错误表面。应增加：

- 双向 Chamfer 或点到面距离。
- P50、P90、P95、P99 和 Hausdorff 距离。
- 表面覆盖率、边界边和连通分量。
- 法向一致性。
- collision Mesh 相对 high-resolution Mesh 的保守性和简化误差。

位姿验收应拆成固定视角重复性、跨视角一致性和相对 GT 的绝对精度，不能共用一个“repeatability”指标。

### 4.5 在线和机器人侧尚未落地

需要补齐在线分割、RGB-D 帧同步、相机位姿来源、手眼标定、机器人 SDK、IK/规划器、夹爪驱动、安全限制、
超时、重试和失败恢复。接口定义不能替代这些实际实现。

### 4.6 可复现性不足

- FoundationPose 本机配置使用绝对路径，换机器无法直接使用。
- Python/Open3D/FoundationPose/CUDA 环境没有统一锁定。
- 运行报告没有记录代码 commit、依赖版本、GPU、耗时和随机种子。
- 默认 Python 环境无法导入 Open3D，首批重建结果需要切换到另一个环境才能复跑。
- `robocup-grasp` 已建立独立 Git 仓库，核心代码、配置、文档和测试已有稳定基线。

## 5. 改进路线

### P0：打通一个真实物体的最小实机闭环

P0 是下一阶段唯一主线。在 P0 完成前，不应把主要精力用于增加更多公开数据集。

#### P0.1 目标硬件采集与标定

工作项：

- 选定最终或代表性的 RGB-D 相机、机器人和夹爪。
- 采集一个静态杯子的多视角 RGB-D、相机内参、机器人关节状态和时间戳。
- 明确 RGB 与 depth 是否硬件同步、是否已经完成 depth-to-color registration。
- 完成手眼标定并输出具名变换和独立验证报告。
- 用平面、标尺或已知尺寸物体验证深度尺度、偏置和随距离变化的误差。

完成标准：

- 原始采集能转换为严格序列且全部通过校验。
- 标定报告包含样本数量、重投影误差、位姿残差和验证集误差。
- 任一 `T_base_camera` 的来源、时间戳和坐标轴约定可追溯。

#### P0.2 深度预处理与真实 TSDF

工作项：

- 新增可插拔 `DepthPreprocessor`，保持原始数据只读。
- 实现尺度/偏置校正、深度跳变过滤、局部滤波和连通域筛选。
- 将多视角重投影残差、有效像素、深度分布和拒绝原因写入逐帧报告。
- 对异常帧执行拒绝或降权，而不是全部等权融合。
- 必要时增加点到面 ICP 或 RGB-D odometry，对机器人/相机外参做小范围局部优化。

建议初轮完成标准：

- 真实对象 AABB 最大轴误差不超过 5 mm。
- 与独立参考 Mesh 比较时，双向表面距离 P95 不超过 5 mm。
- 输出 Mesh 不包含影响规划的远距离孤立表面。
- high-resolution 与 collision Mesh 都通过几何质量报告。

#### P0.3 在线 mask 与位姿估计

工作项：

- 接入真实任务中的检测与实例分割，输出 mask、类别、置信度和时间戳。
- 分别评测 GT/人工 mask 与预测 mask，量化分割导致的位姿退化。
- 初次检测使用 `register()`，连续帧考虑 FoundationPose `track()`，低置信度时重新注册。
- 增加位姿置信度、超时、跳变检测和无结果状态，禁止用无效位姿继续规划。

完成标准：

- 至少 100 帧独立测试，覆盖距离、方位、遮挡和可见率变化。
- 报告平移、旋转、ADD/ADD-S、投影误差、失败率和延迟分布。
- 固定视角重复性与跨视角一致性分别报告。

#### P0.4 可执行 GraspPlan

工作项：

- 将候选组合成 pregrasp、grasp 和 retreat 位姿。
- 接入夹爪开口、闭合位置或力控制参数。
- 加载机器人与夹爪碰撞模型。
- 对所有候选检查 IK、环境碰撞、对象碰撞、路径碰撞和桌面净空。
- 保存每个候选的接受或拒绝原因，再从可执行候选中按任务代价排序。

完成标准：

- dry-run 输出完整 `GraspPlan`，而非单个 4x4 矩阵。
- 不可达或碰撞候选不会被选择。
- 计划能够在仿真或机器人规划器中完整执行到 retreat。

#### P0.5 低速实抓验收

工作项：

- 实现 `observe -> estimate -> plan -> approach -> close -> lift -> verify -> recover` 状态机。
- 每阶段设置超时、速度限制、急停条件和结构化日志。
- 首轮执行 20 至 50 次低速抓取，记录每次输入、位姿、候选、轨迹和结果。
- 将失败分成分割、位姿、IK、碰撞、接触、夹持、滑落和软件异常。

建议初轮完成标准：

- 无安全事件和未处理异常。
- 每次失败都有明确阶段和原因记录。
- 在单对象、受控桌面场景达到至少 80% 抓取成功率，再扩大对象与场景范围。

### P1：建立独立、可解释的评测体系

- 在采集批次 A 或 scene1 建库，在批次 B 或 scene2 评测，避免同轨迹闭环。
- 位姿评测扩展到至少 100 帧，并按距离、可见率、遮挡和视角分桶。
- 同时保留 GT mask 上限结果和预测 mask 系统结果。
- 对固定输入重复推理以测量随机重复性，对不同视角测量一致性。
- 报告位置各轴误差、旋转误差、ADD/ADD-S、2D 投影误差、失败率和 P50/P95 延迟。
- 增加至少一个无柄或弱纹理对象和一个存在对称性的对象。
- 把真实手眼标定误差加入最终 `T_base_grasp` 误差预算。

### P2：工程化与持续回归

- 配置路径支持相对配置文件解析或环境变量，移除受版本控制配置中的机器绝对路径。
- 使用 lock file、Conda 环境或容器锁定 Python、Open3D、CUDA、PyTorch 和 FoundationPose commit。
- 记录模型权重哈希、数据 manifest、代码 commit、硬件、运行时长和随机种子。
- 将代码和小型配置纳入 Git；大数据、权重和运行输出继续使用 manifest、DVC、NAS 或对象存储。
- 为 Open3D 增加合成 RGB-D 重建集成测试，为 FoundationPose 增加 GPU smoke test。
- 增加配置内参与序列内参、配置 depth scale 与序列 metadata 的一致性检查。
- 在执行昂贵评测前检查输出目录，避免 GPU 推理结束后才因覆盖保护失败。

## 8. 下一迭代执行清单

按顺序执行，前一项未获得结果前不扩大范围：

1. 确认目标相机、机器人、夹爪及其坐标约定。
2. 采集一个真实杯子的多视角序列并建立数据 manifest。
3. 完成深度偏置和手眼标定的独立测量。
4. 实现并对比深度预处理基线，产出 raw/processed/GT 或参考 Mesh 的统一报告。
5. 让真实 TSDF 通过尺寸和表面质量门槛。
6. 接入预测 mask，完成不少于 100 帧的独立 FoundationPose 评测。
7. 实现 `GraspPlan`、夹爪模型、IK 和碰撞筛选。
8. 先在仿真或规划器 dry-run 中执行完整轨迹，再进行低速实抓。
9. 根据 20 至 50 次实抓失败分布决定下一轮优化重点。

## 9. 当前最重要的决策原则

- 不用 `depth_gt` 成绩代表真实相机精度。
- 不用 GT mask 的位姿成绩代表在线系统精度。
- 不用同场景重建 Mesh 的评测代表跨场景泛化。
- 不用矩阵组合成功代表候选可达、无碰撞或可执行。
- 不用 AABB 尺寸通过代表 Mesh 表面完整。
- 不用接口存在代表机器人集成已经完成。
- 后续每个“完成”结论都必须对应可复现产物、明确指标和通过门槛。
